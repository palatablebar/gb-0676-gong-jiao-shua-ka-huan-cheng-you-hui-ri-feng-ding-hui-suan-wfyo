# 数据定义

刷卡事件以event_id去重，card保留前导零。route支持1路/01等别名。event_time必须带偏移；业务日为Asia/Shanghai。result仅success可作为行程，失败刷卡隔离。reported为实扣人民币元。票价F1至2026-11-01前为2元，F2为2.50元。

跨线路换乘必须在上一次实际付费行程后60分钟内，恰好60分钟排除。同线路无优惠；零付费行程不能延长换乘锚点。先扣1元换乘优惠，再对卡号业务日施加6元封顶。每条基本票价=实算扣费+换乘优惠+封顶优惠。

## 接驳方向裁决（M5）

参数 `direction_mode` 取值 `both`（默认，双向对称）或 `feeder`（仅接驳方向），`feeder_links` 为 `[支线, 主干线]` 配对列表。

- `both`：同一组接驳线路双向享受优惠，行内 `transfer_direction` 记为 `接驳方向`（支线→主干线）或 `返程方向`（主干线→支线）；非接驳组跨线记 `跨线换乘`，同样享受优惠。
- `feeder`：只有支线→主干线给优惠；主干线→支线的返程按 `仅承认接驳方向：返程不享换乘优惠` 拒绝；非接驳组跨线按 `两线不属于同一组接驳线路` 拒绝。
- 其他拒绝理由：`无上次付费行程，不构成换乘`、`同线路乘车不享换乘优惠`、`超出半开换乘窗（恰好60分钟排除）`。每行均输出实际采用方向（`transfer_direction`）与裁决/拒绝理由（`transfer_reason`）。
- 方向规则非法（未知模式、配对缺支线或主干线、feeder 模式缺配对）在 M5 快速失败，错误码 `BAD_DIRECTION_RULE`；批次接口收到该错误时不写库，完整沿用最近一次旧版日账并在响应与页面标注 `fallback`。

## 卡日账与封账（M7）

每张卡每个业务日恰好一份日账（`daily_ledgers`），含笔数、基础票价、换乘优惠合计、封顶减免合计、封顶应收、实扣、差额与来源行。日账写入 SQLite `daily_ledgers` 表，主键 `(run_id, card, business_day)`，同源重跑 `INSERT OR IGNORE` 复用，不会多出一笔占额。封账前跨模块守恒闸口：来源行平衡、日账应收/申报合计与 M6 清分合计相等、逐笔覆盖不重不漏、分币守恒；任一不平抛 `UNBALANCED`/`LEDGER_CROSS_CHECK`/`LEDGER_NOT_BALANCED`，不许封账、不写日账。

业务ID和超大整数按文本保形；Decimal参与数量金额计算，对外序列化为字符串。哨兵集合定义在app/values.py，缺失值不能当零。所有时间带UTC偏移，先转UTC比较，业务日按指定地区划分。区间统一[start,end)。重复业务键保留第一条、完全相同行计重复；值冲突行隔离且保留原值。空文件、全空白、仅表头分开拒绝。

运行清单包括输入sha256、规则版本、参数、生成时刻与耗时。源行编号以CSV解析器的物理结束行号表示，引号内换行不增加记录数。输入超过4MB返回413，非法表头和类型返回422，失效版本复核返回409。
